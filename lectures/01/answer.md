# 第1回 解答

## 演習

- 講座固有の質問は、下記の発展課題の比較実験にも含めて確認した。両モデルとも確かな情報がないと明示し、「基礎・応用・発展」などの一般的な区分を例示した。
- 用語集 `data/glossary.json` の `homework-levels` の正しい区分は「基礎・実装・発展」であり、1つに取り組めば完了する。資料を渡していない素のLLMは、この講座固有の定義を正確には回答できなかった。
- 計測例：軽量モデルのLoRA質問（request_index=1）は入力28、出力102トークンだった。`app/ask.py` にも演習の入力・出力・推論トークン表示を追加した。

## 宿題

- **取り組んだレベル：発展**
- **やったこと：** 2モデル×2質問×各3回、計12回のGemini API呼び出しを実行し、応答時間・入力/出力/推論/合計トークン数と回答本文を記録した。
- **実行日時：** 2026年10月26日 14:05:21〜14:09:59（Asia/Taipei、UTC+8）。待機を含む所要時間は約277.6秒。
- **結果：** 12回全て正常完了。APIエラー、空回答、出力上限による打ち切りは0回。

### 1. 実験条件

| 項目 | 設定 |
|---|---|
| モデル | `gemini-3.5-flash-lite`、`gemini-3.8-flash` |
| 質問 | LoRAの説明、講座固有の宿題の3レベル（双方200字程度を指示） |
| 回数 | 各条件3回。モデルごとに6回、合計12回 |
| 生成上限 | `max_output_tokens=2048` |
| temperature / 推論設定 | モデルの既定値 |
| 会話履歴・検索・ツール | 使用しない |
| 実行順 | 固定seed `20261026` で混ぜる |
| 待機 | 各呼び出しの終了後に20秒（最後は不要） |
| SDKの自動再試行 | 無効化（`attempts=1`） |
| タイムアウト | 60秒 |
| ウォームアップ | なし。クライアントは実験全体で再利用 |
| 実行環境 | Python 3.12.12、google-genai 2.31.0。依存パッケージは講座の `uv.lock` の固定版 |

APIのモデル一覧で両モデルの利用可能性を確認してから、生成の12試行を行った。
この一覧取得は生成試行の計測には含めていない。
レスポンスの `model_version` も、それぞれ指定したモデル名と一致した。
実際に送った全文は `benchmark_questions.json` と結果の `metadata.json` に保存した。

実行コマンド（リポジトリのルート）：

```bash

  --models gemini-3.5-flash-lite gemini-3.8-flash \

```

上記の保存先には今回の結果が既にある。追試時は `--out` を省くと新しい日時付きフォルダに保存できる。

### 2. 計測方法と記録ファイル

応答時間は `time.perf_counter()` でSDK呼び出しの直前から返却直後までを測った。
待機・ファイル保存・クライアント作成は含まない。ネットワーク通信、推論、生成、SDK処理などを含むため、純粋な推論時間やTTFTではない。
入力・出力・推論・合計のトークン数は `response.usage_metadata` の値をそのまま記録した。
取得できない値は `null` とし、0で補完していない。

成果物は全て `results/20261026-baseline/` に保存した。

| ファイル | 内容 |
|---|---|
| `metadata.json` | 実験条件、質問全文、環境、UTCでの実行日時、完了状態 |
| `raw.jsonl` | 各試行の回答本文・トークン数・時間・終了理由などの一次記録 |
| `measurements.csv` | 各試行を表形式にしたデータ |
| `summary.csv` | モデル×質問ごとの平均・中央値・最小最大・標本数 |
| `summary.md` | 閲覧用の比較表 |

### 3. 実測結果

各セルは正常完了した3回の平均。応答時間の中央値も併記する。

| モデル | 質問 | 成功/試行 | 平均秒 | 中央値秒 | 入力token | 出力token | 推論token |
|---|---|---:|---:|---:|---:|---:|---:|
| gemini-3.5-flash-lite | LoRA | 3/3 | 1.557 | 1.309 | 28.000 | 102.333 | 未返却 |
| gemini-3.8-flash | LoRA | 3/3 | 6.603 | 7.374 | 28.000 | 103.000 | 559.667 |
| gemini-3.5-flash-lite | 宿題の3レベル | 3/3 | 1.603 | 1.480 | 45.000 | 123.333 | 未返却 |
| gemini-3.8-flash | 宿題の3レベル | 3/3 | 9.405 | 9.531 | 45.000 | 120.667 | 594.667 |

モデルごとの6回合計は、軽量モデルが入力219・出力677・API報告合計896トークン、
上位モデルが入力219・出力671・推論3,463・API報告合計4,353トークンだった。
軽量モデルの推論トークン数は全試行で未返却であり、推論が0だったと断定はしない。

### 4. 結果の解釈

**時間とトークン数：** 今回の条件では軽量モデルの応答が速かった。
LoRA質問の平均は1.557秒と6.603秒、講座固有の質問では1.603秒と9.405秒だった。
一方、回答の出力トークン数は両モデルで近い。上位モデルには回答以外に推論トークンが記録されており、
回答の長さだけでは内部の処理量やAPI報告合計を説明できないと分かった。
ただし推論設定、モデル構成、ネットワーク、サーバー混雑等を個別に制御していないため、時間差の原因を推論だけに特定することはできない。

**回答内容：** LoRAへの6回答は、元の重みを固定して低ランク行列を追加・学習することと、全パラメータを更新するフルファインチューニングとの違いを概ね説明できていた。
一部の「同等の性能を維持できる」という表現は、条件による違いを省いており、全ての場合の保証として読むべきではない。
講座固有の質問への6回答は全て不確実性を明示したが、正しい3区分「基礎・実装・発展」を講座の定義として答えた回答はなかった。
どちらのモデルにも用語集を渡していないため、モデルを上位に切り替えるだけでは講座固有の知識は補えなかった。
この観察は手作業での内容確認であり、厳密な品質スコアの比較ではない。

**不確実性の扱い：** 質問に「確かな情報がない場合は、その旨を明示」と入れている。
したがって今回の結果から、無条件でも両モデルが常に不明と答えるとは言えない。
また、回答の「公開情報を確認できない」という文言は、Web検索を実行した事実を意味しない。この実験には検索ツールを接続していない。

### 5. 無料枠のレート制限との関係

レート制限にはRPM（毎分のリクエスト数）、TPM（毎分の入力トークン数）、RPD（1日のリクエスト数）があり、
モデル・プロジェクト・利用枠によって変わる。最新のアカウント固有の上限値はAI Studioで確認する必要がある。
今回、アカウント固有の上限の数値は取得していない。

- 各モデルへの生成リクエストは6回ずつだった。
- 全体で呼び出し終了後に20秒ずつ待つため、連続した呼び出し開始の間隔は20秒より長くなる。これは全体で毎分約3回未満のペースだが、利用上限を必ず満たす保証ではない。
- 各モデルの入力は合計219トークンと小さく、長いコンテキストを渡す実験ではない。より長い資料を渡す場合にはTPMにも注意が必要になる。
- 429や503は観測されなかった。今回エラーが出なかった事実から、正確な上限値や他の時間帯での成功は推定できない。
- 429の場合は記録して中断する設計にした。日次枠を使い切った場合は短時間待つだけでは復旧しないため、連続再試行せず利用状況を確認する。
- 1回の応答が速くてもRPM/RPDの上限は別に存在する。実際の運用では、速度だけでなく処理できるリクエスト数も考える必要がある。

トークン数は計測したが金額・請求状態は取得していないので、実際の料金はこの実験からは確定できない。

### 6. 検証と限界、次に試すこと

- APIを使わない全テストは **19件通過**（既存11件＋追加8件）。使用量の欠損、失敗・打ち切りの除外、429時の中断、途中終了時のログ保存を確認した。
- 実APIの12試行も全件正常完了した。
- 各条件3回で質問も2種類だけなので、一般的な優劣、有意差、混雑時の性能までは結論づけられない。
- ウォームアップがなく、モデルごとの推論の既定設定も異なり得る。通常の利用条件での小規模な観察として扱う。
- 次は質問だけを変えて200字と500字を比較し、出力トークン・応答時間・打ち切りの有無を調べたい。条件を一つずつ変えることで影響を考えやすくする。
